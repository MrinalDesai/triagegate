About TriageGate

TriageGate is an AI-powered operations platform that automatically classifies, routes, and resolves incoming support tickets through a multi-stage decision ladder. Each ticket travels through up to four rungs — SVM Gate, Voter Agreement, Bob Investigator, and Human Review — stopping at the earliest rung that can confidently resolve it. The system combines a deterministic keyword scorer, an SVM classifier, and a k-nearest-neighbour classifier whose votes are reconciled before any escalation decision is made. TriageGate is built on IBM Bob 2.0; when WatsonX credentials are present, Granite foundation models are additionally available as a tiebreak layer.

Escalation and Human-Approved Investigation

When a ticket cannot be resolved by the statistical rungs, it is escalated to the Bob Investigator mode. The investigator performs root-cause analysis, traces the fault to specific files, and formulates a candidate patch. Before any code is modified, the investigator classifies the fix risk:

  • High-risk changes (payment processing, authentication, destructive database operations) are never applied automatically. The investigator presents the proposed patch as a unified diff, states the risk justification, and explicitly asks a human operator for approval. The patch is applied only after the operator confirms in-session.
  • Low-risk changes (pure logic fixes, read-only paths) may be applied immediately, with the report flagged as auto-applied.

After a patch is applied, the full test suite runs automatically. The resulting report — root cause, patch summary, unified diff, and before/after test counts — is stored and surfaced in the Console tab alongside a verdict badge (Fix Verified, Fix Failed, or Needs Human) and a risk badge (High Risk / Low Risk).

Automated Testing

TriageGate integrates with the project test runner at every escalation boundary. After a patch is applied by the Bug Investigator, the system automatically executes the test suite, compares pass/fail counts against the baseline, and records the delta. This loop ensures that no patch lands without evidence it improves coverage, and the side-by-side tests_before / tests_after view in the Console makes regressions immediately visible to the on-call engineer.

Application Maintenance

Beyond reactive debugging, TriageGate supports proactive application maintenance through the Ladder Stats view. Real-time rung counters reveal how tickets distribute across the resolution stages, making it easy to spot when SVM confidence is degrading (rising escalation rates) or when a domain is accumulating unresolved tickets. These signals feed back into retraining pipelines and on-call rotation decisions, closing the loop between automated triage and long-term system health.
